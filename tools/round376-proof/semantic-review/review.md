# A376 static scheduling review

This review covers frozen A376 main `7c815fe835a41a7d82dedd5b55dd14136b34ee957e35b14c14688a3a6c2826ff` against the selected371 original main `02661f93bc65fc35d359c80e19d82578968ab68725e8b325e48c630c3e27310c`. No concrete correctness counterexample was found for the stated input domain and the actual requested worker range1..12. This is source reasoning and byte binding, not an executed scheduler model, exhaustive proof, sanitizer result or performance claim.

The substantive changes are4MiB raw grid points instead of one raw range per worker, a shared atomic part index, an outer range-claim loop around the unchanged row parser, and an average reserve hint based on file.size/threads. Chunk, LocalEndpoints, latency/error/key packing, wide storage, hour aggregation, percentile selection and ordered output remain unchanged. The binding helper checks that everything after the parsing parallel call is byte-identical to371 and that all other runtime/build/metadata files match371 except the disclosed README and frozen PERF notes.

## Exact boundary coverage

Write n=file.size, B=2^22 and k=ceil(n/B). For an interior raw position x=iB, the code keeps x when its preceding byte is LF; otherwise it selects one past the first LF at or after x, or EOF when there is no such LF. Each selected point is a row start or EOF. For increasing raw positions this alignment is nondecreasing: if a row end lies between the positions, the earlier search stops no later than that row end; if none lies between them, both searches reach the same next row end or EOF. Looking at x[-1] is guarded, and memchr receives exactly [x,end); newline+1 never exceeds end.

Together with b0=base and bk=end, the monotone half-open intervals [bi,b(i+1)) partition [base,end). Adjacent searches may produce equal boundaries; their interval is empty and the while(p<limit) body runs zero times. No valid LF-delimited row is split, skipped or processed twice. This argument does not assume sorted timestamps or a bound on interleaving among log shards. It does not depend on a fixed endpoint catalogue.

For n=0, parts=0 and the one-element boundary vector receives base=end at both front and back. Every worker exits before indexing a part, and the existing empty-hour output path remains available. For0<n<=B there is one full-file interval. An interior raw grid point is strictly below EOF because i<ceil(n/B). A grid point already after LF is preserved; a grid point on LF advances past it unless it is also the start of an empty line. LF-only/empty-line inputs remain outside the valid request grammar, with existing parser rejection paths. A final unterminated row remains in one interval ending at EOF and is not silently dropped; the unchanged parser requires its LF.

The competition target and native development target are64-bit. Under the existing n<=UINT32_MAX guard, n+B-1 fits size_t on these targets, k<=1024, and every interior iB<n. This review does not claim the same ceil arithmetic supports near4GiB files on a32-bit size_t target. Overlapping newline searches can rescan an unusually long extended row; no performance bound for inputs beyond the frozen endpoint grammar is inferred from correctness of the partition.

## Atomic claims and earliest-hour offsets

next_part is initialized to zero before the workers start. Each fetch_add(1, relaxed) is an atomic read-modify-write in one modification order, so every successful claim has a distinct index. A worker checks part>=parts before reading boundaries[part] or boundaries[part+1]. Each worker claims only after finishing its preceding interval; its own indices therefore increase strictly, and its byte ranges are nondecreasing even when some are empty. Each successful phase consumes every index below parts. At most one final out-of-range claim occurs per worker, so the counter advances at most parts+threads<=1036 times. Counter wrap is excluded on the actual targets without an assumption about the thread interleaving.

The counter allocates task identities; it does not publish boundary data or parsed records. Boundaries and shared objects are initialized before thread creation. The existing parallel helper joins workers before phase-two aggregation. Those start/join relationships, rather than the relaxed claim order, provide the required initialization and result visibility.

Within a worker, rows are processed in increasing file-offset order across its monotonically claimed intervals. Consequently the first encountered row for any hour is the minimum offset for that worker's hour, even when hour values themselves are unsorted. The unchanged aggregation minimum over all workers recovers the minimum offset for the whole hour. A valid line offset is below file.size<=UINT32_MAX, so UINT32_MAX remains a distinct unset sentinel. The hour label copied from that minimum therefore remains unchanged by the new assignment of rows to workers.

## State and full-value preservation

There is one Chunk and one LocalEndpoints instance per requested worker, not per range. Only that worker mutates its parsing Chunk and local cache. A worker keeps those objects across claims; the mutable p/limit pointers are local to each claim. Shared endpoint publication and full-key equality are the byte-identical original implementation. Endpoint numeric IDs may be assigned in a different order, but they still identify complete equal keys; final endpoint ordering is unchanged.

For each worker/hour the packed record is appended before a wide latency, and the wide value is appended exactly when latency>=the original19-bit escape. The later wide cursor scans that same worker/hour record vector in append order. Changing range ownership changes the grouping of records among workers, not the alignment of any record with its escape value or the multiset used for percentiles. All32 latency bits, the error flag, endpoint-capacity failure, full-key fallback, byte ordering and requested/default worker semantics remain unchanged. The new reserve_hint is only a capacity request; vector growth is still available and no record count is limited by the hint.

The same worker_count() guard permits1..12 workers and defaults to12. Small inputs may leave some of those workers with no ranges; this changes utilization, not the thread budget or output contract. No affinity, host scheduling policy, worker default, compiler flags, PGO seed, cached result or persistent input state is introduced.

## Exceptions and joining

Boundary-allocation failures occur before worker launch and reach the unchanged outer exception handler. During parsing, the original parallel helper catches a worker exception into its own exception slot, lets other launched workers finish, joins them, and rethrows before the aggregation phase begins. A failed record append followed by a failed wide append cannot yield a successful inconsistent scatter because that exception prevents phase two. The same applies to cache allocation, endpoint overflow and row-validation failures. Diagnostic selection among simultaneous failing workers may change with task assignment; identical error text/order is not claimed.

If vector growth or thread creation in parallel itself throws, already created jthreads are destroyed and joined during unwinding. Every launched parser can independently drain available parts; there is no required unstarted owner role, consumer or publication marker. The new range counter creates no dependency on worker0 being launched. Original shared-interner publication/progress requirements remain unchanged. This is a source-level argument under ordinary worker progress, not a guarantee of operating-system fairness or an executed startup-failure test. No C357 cancellation/startup proof is transferred to this A parser.
