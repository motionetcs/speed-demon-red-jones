# Track D: exact bidirectional shortest paths

Read `/data/graph.txt` and `/data/queries.txt`; write exactly `/out/distances.txt`. Local `--data` and `--out` options are supported. Standard C++20/OS facilities only. `SPEED_DEMON_THREADS=1` through `12` selects query workers; default12, retained after the current compact-loader configuration scored higher with twelve workers.

At12 total workers,8 readers parse newline-aligned chunks and4 owners receive12-byte full-width edge records through separate forward/reverse SPSC channels. Each4096-node block has exactly one owner in both passes. One requested worker runs serially; smaller settings keep the requested total. An ordered empty batch ends each channel, and exceptions cancel blocked peers before joining. No input locality or special file order is assumed.

The first pass counts exact outgoing/incoming degrees. Only a node's block owner updates its byte counter, so updates need no atomic read-modify-write. Every255→0 wrap adds256 to that owner's private spill map. Joined totals produce prefix sums and release the degree arrays. The second pass claims disjoint CSR slots using the same exclusive ownership.16-row scratch prefetches degree/cursor/edge locations. Cursors are16-bit offsets relative to4096-node block bases only when the complete edge interval is at most65535; wider blocks use full absolute uint32 cursors. Every input edge is counted once and stored once in each direction. Full node IDs/weights, duplicates, parallel/self edges and zero weights are retained. All loaders/queues join and release before queries.

A graph with up to2^21 nodes uses a uint32 edge word:21 bits for destination and11 for a small weight. Sentinel2047 redirects to the exact uint32 side table, including weights equal to2047. Larger node spaces retain six-byte uint32-destination/uint16-w32 entries with sentinel65535. The graph header selects one template specialization before scattering or searching, so edge loops use constant shifts and no per-edge representation branch. Every legal larger node ID and weight retains its full value. Packed fallback fields are copied into aligned scalar locals before constructing return objects. The full graph needs40 MB of adjacency entries instead of60 MB; the specialized/full-training version improves real board K to14.277374 (57.732417 points). The earlier variable-width decoder scored lower and is rejected.

Queries use bidirectional label correction with radix queues grouped into64-distance bands. Every queued entry retains its exact uint64 distance; banding changes only processing order. Up to32 entries from one current band are prefetched and processed together. Labels improved within the same band are requeued and can be processed again; no settled flag suppresses those improvements. Stale labels are checked immediately before expansion, including after earlier batch items may have improved them.

Queue sizes choose the expansion direction, limiting work imbalance even when a source's initial edge weights are very large. Meeting paths give actual path-length upper bounds. A queue minimum is the lower boundary of its earliest nonempty band, so adding both minima gives a conservative stopping bound. Stopping is checked only between fully processed batches. Work below each boundary has been exhausted, and nonnegative weights cannot create a lower band. Lowering the bound can require extra work but cannot justify an early stop. Compact entries hold uint32 distances and nodes in one uint64; larger distances use an exact full-width queue. Neither stored labels nor answers are rounded.

Each worker owns forward and backward distance maps. Their common labels use four-byte words in eight-entry buckets. The bucket index supplies the low node-ID bits; the stored tag supplies every remaining bit of a21-bit node ID. This reconstructs the complete ID, rather than using a probabilistic fingerprint. The low field stores distance+1, leaving zero as an empty slot. Growth reconstructs every ID and preserves its exact distance. Touched slots are cleared between queries.

Nodes or distances that do not fit, and full buckets, use a full-node/full64-bit fallback map. A smaller label can migrate into packed storage; it always takes precedence over any older, larger fallback value. SSE2/NEON compares four slots at once, with a scalar fallback elsewhere. Slots remain a dense occupied prefix within a bucket because no individual label is deleted during a query. Consequently the first matching exact tag or empty slot is sufficient. No distance is rounded, no node is dropped, and workers never share mutable query labels.

An atomic job index assigns each query once. Each answer has one writer; final output preserves input query order. Unreachable pairs emit`-1`; source=target emits0. Graph storage is O(nodes+edges), and query workspaces scale with explored frontiers. Loading, allocation/reset, queries, and output are all timed.
